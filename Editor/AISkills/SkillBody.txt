# Authoring TutorialKit tutorials

You are helping author, configure, test, and debug **TutorialKit** tutorial sequences in this Unity
project. TutorialKit plays branching, multi-step onboarding flows: dim/highlight (vignette), animated
hand/arrow pointers, styled text boxes, input gating, custom game commands, and persistent progress.
It talks to the game only through adapters, and scene elements are addressed by **string ids**.

Follow this workflow.

## 1. Discover the game's features

- **Targets** — anything a tutorial highlights or points at needs a `TutorialTarget` component with a
  stable `Id` (falls back to the GameObject name). Find existing ones by searching the project for
  `TutorialTarget`, or add them to the buttons/objects the flow touches. Note the ids you'll reference.
  For elements created/selected at **runtime** (e.g. spawned grid cells), register **dynamic targets**
  from game code — no scene component needed:
  `TutorialTargets.RegisterDynamic("cell_a", () => FindMyCell())` (a resolver found by game logic each
  frame), or `TutorialTargets.RegisterRect("id", () => someScreenRect)` to control position/size
  directly. Highlights and pointers then follow whatever the resolver returns.
- **Signals** — game code raises named signals via `TutorialDirector.Current.Signals.Emit("id")` or a
  `TutorialSignalEmitter`. `Wait For Signal` nodes await them. Grep for `.Emit(` / `TutorialSignalEmitter`.
- **Commands** — game code registers async commands via `Commands.Register("id", ...)`. `Game Command`
  nodes invoke them. Grep for `Commands.Register(`.
- **Persistence / input-lock** — defaults exist; a game may install custom adapters (`SetPersistence`,
  `SetInputLock`). Not usually needed for authoring.

## 2. Author the tutorial

**Create and edit the tutorial as a `TutorialGraph` ASSET** — never build it dynamically at runtime.
Use the Unity MCP `script-execute` tool to run C# that authors the asset through the editor API
`TutorialKit.Editor.TutorialGraphAuthoring`. This produces a real `.asset` (the exact thing the graph
editor opens) with the mandatory Start/End nodes, stable ids, connections and auto-layout — no manual
`AddNode`/`SetEdge`/`CreateAsset` plumbing, and it stays editable in the graph window.

### A. Create a new tutorial

```csharp
using UnityEngine; using UnityEditor; using TutorialKit; using TutorialKit.Editor;
public static class MakeTut {
  public static void Run() {
    var g = TutorialGraphAuthoring.CreateGraph("Assets/Tutorials/Shop.asset", "Shop Intro");
    var start = TutorialGraphAuthoring.GetStart(g);
    var end   = TutorialGraphAuthoring.GetEnd(g);

    var t1 = TutorialGraphAuthoring.AddNode<ShowTextBoxNode>(g);
    t1.Title = "Hi"; t1.Body = "Tap the shop."; t1.Placement = TextBoxPlacement.Top;
    var v1 = TutorialGraphAuthoring.AddNode<ShowVignetteNode>(g);
    v1.Target = new TutorialTargetRef("shop_button"); v1.Shape = HighlightShape.Circle;
    var p1 = TutorialGraphAuthoring.AddNode<ShowPointerNode>(g);
    p1.Gesture = PointerGesture.Tap; p1.Target = new TutorialTargetRef("shop_button");
    var w1 = TutorialGraphAuthoring.AddNode<WaitInputNode>(g);
    w1.Kind = WaitInputKind.TapOnTarget; w1.Target = new TutorialTargetRef("shop_button");

    // wire Start → t1 → v1 → p1 → w1 → End (Chain replaces the initial Start→End edge)
    TutorialGraphAuthoring.Chain(g, start, t1, v1, p1, w1, end);

    TutorialGraphAuthoring.Layout(g);  // arrange nodes (same as Auto Layout)
    TutorialGraphAuthoring.Save(g);    // validate + save the asset
  }
}
```

### B. Edit an existing tutorial
Load the asset and mutate it the same way, then re-layout + save:
```csharp
var g = TutorialGraphAuthoring.Load("Assets/Tutorials/Shop.asset");
var praise = TutorialGraphAuthoring.AddNode<ShowTextBoxNode>(g); praise.Title = "Nice!";
// re-route the flow through the new node (Connect uses a single edge, replacing on that port)
TutorialGraphAuthoring.Connect(g, existingNode, praise);
TutorialGraphAuthoring.Connect(g, praise, TutorialGraphAuthoring.GetEnd(g));
TutorialGraphAuthoring.Layout(g); TutorialGraphAuthoring.Save(g);
```

### `TutorialGraphAuthoring` API (namespace `TutorialKit.Editor`)
- `CreateGraph(path, displayName?, description?)` → new `.asset` with Start + End already wired.
- `Load(path)` → open an existing asset to edit.
- `AddNode<T>(g)` / `AddNode(g, "TypeId")` → add a node; **set its public fields on the returned object**
  (see the node reference below for each node's fields).
- `Connect(g, from, to, port?)` → one flow edge (replaces on that port; `port` defaults to the first
  output — pass `"True"`/`"False"` for a Condition). `ConnectFanOut(...)` for concurrent branches.
- `Chain(g, a, b, c, …)` → wire `a → b → c → …` (usually `Start … End`).
- `ConnectData(g, provider, "Target", consumer, "Target")` → a typed target/data edge.
- `GetStart(g)` / `GetEnd(g)`, `EnsureStartEnd(g)`, `Layout(g, vertical:false)`, `Save(g)`.

Then open **Window ▸ TutorialKit ▸ Tutorial Graph Editor** to review/tweak it — it's a normal asset.

### C. Remote / portable JSON (optional)
For content loaded at runtime from a URL/file, use the type-tagged JSON that round-trips every node
(including custom ones):
```json
{ "tutorialId":"shop", "displayName":"Shop", "entry":"<nodeId>",
  "nodes":[ { "type":"ShowTextBoxNode", "id":"n1", "data":"{...JsonUtility fields...}" } ],
  "edges":[ { "from":"n1", "port":"Out", "to":"n2" } ] }
```
`data` is `JsonUtility.ToJson(node)` (escaped). Load at runtime with
`RemoteTutorialLoader.LoadFromJson(json)` or `LoadFromUrlAsync(url)`. To produce a correct JSON file,
author the asset (A) then **Export** from the graph editor toolbar, or call `TutorialJson.ToJson(graph)`.

## 3. Configure it to run

Add a `TutorialTrigger` component in the scene, assign the graph, and set When = On Start / On Signal /
Manual, plus gating (only-if-not-completed, conditions). Or start from code:
`TutorialDirector.EnsureExists().Play(graph);`

### Tutorial settings (per graph)

Every graph carries a `TutorialSettings` block — edit it in the graph editor's side panel under the
**Tutorial** tab (the Node tab shows the selected node), in the graph asset's inspector, or from code
via `graph.Settings`. The director enforces it for every entry point (trigger, code, remote), so you
never re-implement this gating:

| Setting | Meaning |
| --- | --- |
| `PlayMode` | `SingleUse` (default — plays once ever, completion saved), `Recurring` (plays every trigger, nothing saved — hints), `OncePerSession` (once per app run) |
| `MaxPlays` | Recurring only: stop after N completed plays. 0 = unlimited |
| `CooldownSeconds` | Recurring only: minimum real seconds between plays; survives a restart |
| `WhenBusy` | Triggered while another tutorial runs: `Interrupt` (default), `Ignore`, `Queue` |
| `LockInputWhilePlaying` + `InputLockGroup` | Hold an input lock for the whole tutorial |
| `PauseGameWhilePlaying` | `Time.timeScale = 0` while it plays (overlay animations are unscaled) |
| `AllowSkip` | Whether `handle.Skip()` works. Off = mandatory tutorial |

```csharp
var graph = TutorialGraphAuthoring.CreateGraph("Assets/Tutorials/LowAmmoHint.asset");
graph.Settings.PlayMode = TutorialPlayMode.Recurring;
graph.Settings.MaxPlays = 3;              // nag at most 3 times
graph.Settings.CooldownSeconds = 120f;    // and no more than once every 2 minutes
graph.Settings.WhenBusy = TutorialBusyPolicy.Ignore;  // never interrupt a real tutorial
```

Ask `director.CanPlay(graph, out var reason)` to test the gating yourself; `Play(graph, force: true)`
bypasses it. `graph.Repeatable` still works as a legacy alias for `PlayMode != SingleUse`.

### Project-wide default styles (Window ▸ TutorialKit ▸ Settings)

`TutorialKitSettings` (a ScriptableObject in a `Resources` folder) holds default styling so a whole
game reads consistently without setting it on every node:
- **Vignette defaults** — shape, overlay colour, softness, padding, corner radius, fade. A Show Vignette
  node with **Use Global Style** on (the default) draws with these; turn it off to use the node's own
  fields. So restyle every highlight from one place by editing the vignette defaults.
- **Text box defaults** — panel/accent/text colour, body alignment, typewriter speed, animation. The
  built-in default text box uses these. A Show Text Box node's `BodyAlignment = Default` and
  `TypewriterCps = 0` resolve to the defaults; set explicit values to override per node.

Body text alignment (`Left` / `Center` / `Right` / `Justified`) is on the Show Text Box node.
Pointer gestures include `DoubleTap` (two quick taps then a pause) alongside Point/Tap/Swipe/Drag/Merge.

## 4. Test it (via Unity MCP)

1. Make sure the scene has the referenced `TutorialTarget` ids and a trigger (or a controller that calls
   `Play`). Save the scene.
2. `assets-refresh` to compile. Wait for `Library/ScriptAssemblies/*.dll`; check `Logs/Editor.log`
   (strip `\r`) for `error CS`.
3. Enter play: `editor-application-set-state {"isPlaying":true}`; poll `editor-application-get-state`
   until `IsPlaying:true`.
4. Screenshot with `screenshot-game-view` to see the overlay.
5. To advance blocking text boxes/taps in a headless run, invoke the continue button or simulate input
   via `script-execute`, then screenshot again.

## 5. Debug it

- Open **Window ▸ TutorialKit ▸ Tutorial Graph Editor**, load the graph, press **▶ Test in Play** — the
  currently-executing node pulses in the graph.
- `console-get-logs` shows warnings like unknown target ids / missing commands.

## Environment gotchas (important)

- **TMP text renders blank** until *TMP Essential Resources* are imported (Window ▸ TextMeshPro).
- The Editor **throttles the play loop when its window is unfocused** (headless MCP driving), so
  animations/typewriters freeze. Set `Application.runInBackground = true` via `script-execute` to make
  them advance for screenshots.
- `console-get-logs` returns a **rolling buffer across all play sessions** — always check each entry's
  `Timestamp`; don't assume a log is from the current run.
- An output port may fan out to **several** nodes: those branches run **concurrently** and the flow
  joins when all finish (`graph.AddEdge` for extra connections; `SetEdge` replaces). Use a
  `ConditionNode` (`True`/`False` ports) for either/or branching. Many nodes may converge into one input.
- **Blackboard**: declare variables in the graph editor's Blackboard panel (or `graph.SetBlackboard`).
  Their defaults seed `ctx.Blackboard` at runtime; `SetFlagNode`/`ConditionNode` read & write them by key.
- **Target ports** (teal data ports): a target provider node (`TargetByIdNode`, `TargetByPositionNode`,
  or your own `TargetNodeBase` subclass with game logic) has a `Target` OUTPUT. Wire it into the optional
  `Target` INPUT of a vignette / pointer / text box / wait node to inject the target from a node instead
  of a fixed field. In code: `TutorialGraphAuthoring.ConnectData(g, provider, "Target", consumer, "Target")`.
